# Paper externally administered credential-head HTTPS transport

**Status: NONACTIVATED candidate, never production release. Signup remains CLOSED.**

## Why this exists

Previously `createDisposableCredentialHeadAuthority` accepted a synthetic
`readHead(challenge)` callback. Correct Ed25519 cryptography is necessary
but insufficient: a production verifier needs a tightly bounded, authenticated
network path to a **separately operated** monotonic latest-head signer.

The candidate `pod-provider/backend/candidates/credential-signed-head-https-transport.js`
implements an explicit POST to `https://<independent-DNS-name>/v1/credential-head`.
Only the SHA-256 **subject hash** and new 256-bit random nonce leave Paper,
not the WebID or account password. It enforces:

- HTTPS with normal certificate validation, no HTTP fallback, redirects,
  proxy injection, retries or cached positive result.
- Exactly one canonical request shape
  `{kind:"paper.credential.challenge.v1",subject,nonce}`.
  The **nonce is generated by the existing pinned Ed25519 verifier**, never
  passed from an incoming HTTP request.
- Bounded response length, content type and no compression; status 200 only.
  Body and signature are strict canonical base64url and passed as raw bytes
  into the **separate signature and latest-state verifier**, which checks
  authority identity, subject, epoch, nonce, Ed25519 signature, digest and
  strict issuance time. TLS alone never authorizes an owner.
- Fail-closed timeout, abort and network errors. No automatic retry
  across ambiguous checkpoint responses.
- An ephemeral self-signed localhost CA is injectable **only** for an
  explicitly disposable `127.0.0.1` proof, never for an arbitrary
  production DNS name. There is no insecure TLS switch.
- The transport is constructed only when `NODE_ENV=test`,
  `PAPER_CREDENTIAL_HEAD_DISPOSABLE=confirmed`,
  `PAPER_CREDENTIAL_HTTPS_DISPOSABLE=confirmed`, and
  `fixtureOnly=true`. Neither the backend service registry nor
  production middleware imports it.

`pod-provider/backend/scripts/proof-paper-credential-head-https.cjs`
uses Node's real HTTPS stack and an ephemeral OpenSSL-generated certificate,
plus a separate ephemeral Ed25519 signer, to exercise valid signed heads,
concurrent distinct challenges, replayed but correctly signed old response,
forged signer, HTTP redirect, oversized response, malformed JSON, aborted
request, timed-out server, untrusted key and invalid endpoint scheme. CI
requires no persistent TLS/signing credentials or external network.

## Remaining hard custody requirements

A successful fresh-signature transport **does not** prove that the
independent signer's own *latest* state cannot be rolled back. Production
must implement and test an outside-administration monotonic register whose
signer key is not present in Paper, whose newly sealed epochs are durably
retained in true independently managed COMPLIANCE Object Lock or equivalent,
and whose recovery and inventory checks cannot be satisfied by a historical
signature. It must fence credential, consent, SAI and PDS epochs before
granting or acknowledging mutations. Separate administrator and reviewer
must certify key custody, IAM/policy/lifecycle controls, live version
retention and genuine cross-store PITR. No live service or account is
provisioned by this candidate.

The existing Cloudflare R2 disposable bucket can test generic S3 transport,
but its lock rules are removable by the same-account administrator. They
are not an independently human-administered immutable latest authority.
Backblaze B2 COMPLIANCE Object Lock or another service under a **separate
administrative boundary** remains a viable independent archive candidate,
subject to provider-specific version/retention and account-role audits.

Do not enable either this candidate or unified signup on the basis of
a passing localhost TLS/Ed25519 simulation. `release=CLOSED`.
